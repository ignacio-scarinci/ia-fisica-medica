Dos workflows diferentes

¿Cuál paradigma es mejor?

La pregunta correcta depende del objetivo.

Para segmentar muchas estructuras conocidas en grandes volúmenes de estudios:

\[ \text{automático} \]

puede ser muy atractivo.

Para estructuras variables, poco frecuentes o definidas durante la interacción:

\[ \text{interactivo} \]

puede aportar mayor flexibilidad.

Dice no alcanza para compararlos

No basta con:

\[ Dice_{\text{automático}} \quad \text{vs} \quad Dice_{\text{interactivo}} \]

También importan:

  • tiempo del usuario
  • cantidad de correcciones
  • errores críticos
  • facilidad de interacción
  • generalización
  • integración clínica

Automatización vs colaboración humano–IA

Dos visiones

Automatización

\[ \text{tarea manual} \rightarrow \text{modelo automático} \]

El sistema intenta reemplazar una tarea específica.

Asistencia

\[ \text{experto} + \text{modelo} \rightarrow \text{tarea asistida} \]

El sistema modifica cómo se realiza la tarea.

Human-in-the-loop

En un sistema interactivo:

la intervención humana no es un fallo del sistema.

Es parte deliberada del diseño.

Importante

El experto aporta conocimiento, intención y contexto.
El modelo aporta velocidad y capacidad de delineación.

¿Dónde colocar al experto?

flowchart TB
    A[Antes] --> A1[Prompt inicial]
    B[Después] --> B1[Revisión / corrección]
    C[Durante] --> C1[Interacción iterativa]

Tres posibilidades:

  1. antes de la predicción;
  2. después de la predicción;
  3. durante un proceso iterativo.

El tiempo total importa más que el tiempo de inferencia

Inferencia rápida ≠ workflow rápido

Un modelo puede tardar segundos en generar una máscara.

Pero luego pueden aparecer:

  • inspección
  • corrección
  • confirmación

Por eso:

\[ \text{tiempo de inferencia} \neq \text{tiempo total hasta máscara aceptable} \]

Tiempo clínico real

flowchart LR
    G[Generación] --> I[Inspección]
    I --> C[Corrección]
    C --> F[Confirmación]

En un sistema interactivo también debemos sumar:

\[ \text{tiempo para generar el prompt} \]

La eficiencia debe evaluarse sobre el workflow completo.

El error también cambia de significado

En un sistema automático

El error puede permanecer oculto hasta la revisión.

flowchart LR
    I[Imagen] --> M[Modelo]
    M --> E[Error]
    E --> R[Detectado en revisión]

En un sistema interactivo

El usuario puede advertir que la salida no corresponde a su intención y modificar el prompt.

flowchart LR
    P1[Prompt 1] --> M[Modelo]
    M --> S1[Salida]
    S1 --> C[Usuario corrige]
    C --> P2[Prompt 2]
    P2 --> M

Esto cambia cómo pensamos seguridad, usabilidad y corrección de errores.

Los dos paradigmas pueden coexistir

No necesariamente hay que elegir uno

Un posible sistema clínico puede combinar:

flowchart LR
    I[Imagen] --> A[Segmentación automática]
    I --> P[Segmentación interactiva]
    A --> O[OARs frecuentes]
    P --> X[Estructuras adicionales / correcciones]

Esto permite:

  • automatizar lo frecuente
  • interactuar en lo excepcional
  • corregir con rapidez
